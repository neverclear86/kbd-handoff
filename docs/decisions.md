# 決定事項

実装を進めるために決めた事項をまとめる。
「Windows 側を常駐させない運用」は利用者と合意したものである。
それ以外は実装の都合で決めたもので、必要に応じて変更してよい。

## 名前

- リポジトリ名は `kbd-handoff` のままとする。
- Linux 側のコマンドは `kbd-handoff-sender`、Windows 側のコマンドは `kbd-handoff-receiver` とする。

## 構成

Cargo ワークスペースで、次のクレートに分ける。

| クレート | 内容 |
| --- | --- |
| `crates/core` | 通信メッセージ、暗号化した通信路、設定の共通部分、キーコード対応表 |
| `crates/sender` | Linux 側。状態機械は `KeySource` トレイトの上に書き、evdev はその実装の1つとする |
| `crates/receiver` | Windows 側。状態機械は `KeySink` トレイトの上に書き、`SendInput` はその実装の1つとする。Linux でもビルドでき、受け取ったイベントをログに出す実装で動作を確かめられる |
| `crates/e2e` | 送信側と受信側を実際の TCP と暗号でつないで確かめる結合テスト |

## 認証と暗号化

- `snow`（Noise Protocol Framework の Rust 実装）を使う。パターンは `Noise_NNpsk0_25519_ChaChaPoly_BLAKE2s` である。
- 事前共有鍵は 32 バイトで、設定ファイルには 16 進数 64 桁で書く。`kbd-handoff-sender gen-psk` で生成する。
- 鍵を知らない相手とはハンドシェイクが失敗し、接続を切る。
- 暗号の処理はすべて `snow` に任せる。`snow` は C のコードを含まない構成（`ring` を使わない）で使い、Windows 向けのクロスビルドを簡単にする。

## 通信のプロトコル

- TCP を使う。Windows 側から Linux 側へ接続する。既定のポートは 47820 とする。
- 1つの Noise メッセージを、2 バイトのビッグエンディアンの長さに続けて送る。
- 受け付ける長さの上限は、ハンドシェイクのメッセージが 256 バイト、それ以降のメッセージが 1024 バイトとする。上限を超える長さが届いたら、本体を読まずに接続を切る。
- 送信側は、ハンドシェイクと `Hello` の受信を終えていない接続を同時に 16 本まで受け付ける。それを超えた接続はすぐに切る。
- 接続した側は、最初に `Hello` で役割を伝える。役割は、キーイベントを受け取る受信プロセス（`Session`）と、切り替えを1回だけ要求する `toggle` コマンド（`Toggle`）の2つである。
- 生存確認：受信側は 1 秒ごとに `Ping` を送る。送信側は、1 秒間なにも送らなかったときに `Ping` を送る。送信側は、受信側の `Ping` を受けたとき、半周期（0.5 秒）以上なにも送っていなければ `Ping` を返す。起床の回数を減らすためである。どちらの側も、3 秒間なにも届かなければ接続が切れたとみなす。
- 再接続：常駐する受信プロセス（`run`）は接続が切れたら、1 秒から始めて最大 10 秒まで間隔を延ばしながら再接続する。1回だけの受信セッション（`session`）は再接続せずに終了する。
- 受信セッションは同時に1つだけとする。新しいセッションが来たら古いセッションを切る。

## 切り替えの要求

- `kbd-handoff-receiver toggle` は、常駐している受信プロセスを経由せず、Linux 側へ直接 `Toggle` の役割で接続して要求を送る。プロセス間通信を別に用意しないためである。
- 受信セッションがつながっていなければ、送信側は占有を始めずに `NoSession` を返す。このときの `toggle` の動作は「Windows 側を常駐させない運用」に書く。
- ホットキーでの要求は、今回は実装しない。

## Windows 側を常駐させない運用

利用者と合意し、Windows 側は常駐させない運用を標準にした。
Linux 側だけを systemd のユーザーサービスとして常駐させる。

- `toggle` が `NoSession` を受けたら、同じ実行ファイルの `session` を、切り離したバックグラウンドのプロセスとして起動して終了する。出力は `session-started`、終了コードは 0 である。設定ファイルは、`toggle` が実際に使ったものの絶対パスを `--config` で渡す。
- `toggle` は `session` の占有の結果を待たない。結果を受け取る経路（パイプなど）を作ると、Windows でのハンドルの継承を扱う必要があり、ここでは確かめられないためである。
- `session` は `Session` の役割で接続し、送信側からの最初の `Ping`（登録の合図）を受けてから、同じ接続で `ToggleRequest` を送る。`ToggleResult` は 10 秒まで待つ。送信側は占有を待つ間も `Ping` を送るので、生存確認だけでは結果が届かないことを検出できないためである。
- `session` は、`Released` を受けたら（2回目の `toggle`、緊急の解放キー、その他の解放）、押されたままのキーを離して終了する。接続が切れたとき、生存確認が途絶えたとき、誤りが起きたときも、キーを離して終了する。再接続はしない。
- `session` の `ToggleResult` が `Grabbed` でなければ、0 以外の終了コード（`Failed` は 3、`NoSession` は 2）で終了する。
- 常駐する `run` は、選択肢として残す。

## Windows 側の実行ファイルの形式と出力先

- ランチャーから起動したときにコンソールウィンドウが開かないよう、GUI サブシステムの実行ファイルにする（`windows_subsystem = "windows"`）。
- `session` は `DETACHED_PROCESS` と `CREATE_NEW_PROCESS_GROUP` で起動する。ジョブの外で起動する `CREATE_BREAKAWAY_FROM_JOB` も試し、拒まれたら外して起動し直す。
- `toggle` と `run` は、親プロセスがリダイレクトした標準エラー出力（ファイルかパイプ）があればそれを使い、なければ親のコンソールに `AttachConsole(ATTACH_PARENT_PROCESS)` で接続する。どちらもできなければ、`%LOCALAPPDATA%\kbd-handoff\receiver.log` に出力する。
- `session` は常にログファイルに出力し、コンソールに接続しない。`toggle` を実行したコンソールに接続すると、そのウィンドウを閉じたときに終了してしまうためである。
- ログファイルは、複数のプロセスが同時に書いても扱えるよう、1 件ごとに開いて追記して閉じる。1 MiB に達したら `receiver.log.old` に名前を変える。

## キー入力の扱い

- 自動リピート（evdev の value 2）は、Windows 側でキーを押す入力として送り直す。`SendInput` で押したキーは Windows 側で自動リピートしないためである。
- 占有を始める前に、全キーが離されるまで待つ。3 秒待っても離されなければ占有をあきらめ、`Failed` を返す。
- 受信側は押されているキーを記録し、`Released` を受けたとき、または接続が切れたときに、すべて離す。

## 緊急の解放キー

- 既定値は `KEY_LEFTCTRL` + `KEY_LEFTALT` + `KEY_LEFTSHIFT` + `KEY_BACKSPACE` の同時押しとする。設定ファイルで変更できる。
- 送信側だけで判定する。受信側が応答しなくても占有を解く。

## Windows 用の実行ファイルのビルド

- ターゲットは `x86_64-pc-windows-gnu` とする。
- ビルドの手順は README に書く。
